발표·QA 시 "왜 이렇게 설계했는지" 답변 준비용. PDF 과제 목표 5가지를 모두 자기 말로 설명 가능해야 함.

## 1. 한 줄 요약

"파일 기반 가계부지만 **CRUD + 검색 + 요약 + import/export**를 모두 지원하고, **JSONL 스트리밍 + 원자적 교체 + 데코레이터**로 운영 안전성을 챙긴 작은 서비스."

---

## 2. 데이터 흐름 (CLI → Service → Store → File)

```
사용자 입력 (대화형 / 옵션)
        ↓
cli.py        argparse + _input_tx()
        ↓
services.py   BudgetService (검증 + 비즈니스 로직)
        ↓
storage.py    TransactionStore / CategoryStore / BudgetStore (제너레이터 스트리밍)
        ↓
data/*.jsonl  영구 저장 (UTF-8 JSONL)
```

**책임 분리 이유**:
- CLI는 입출력 형식만 — 비즈니스 로직 모름
- Service는 검증·정책 — 파일 모름
- Store는 I/O만 — 모델 외 룰 모름

→ 한 계층 바꿔도 다른 계층 영향 X. PDF 과제 목표 2번 "각 계층의 책임 설명" 답변.

## 3. 핵심 설계 결정 (5가지)

### 3-1. 왜 JSONL인가 (CSV 대신)
- **append-only 단순**: 1줄 = 1레코드. 거래 추가 시 파일 끝에 1줄 쓰면 끝.
- **타입 보존**: CSV는 모두 문자열. JSONL은 int/list 그대로.
- **사람이 직접 읽기 가능**: 디버깅 쉬움.
- **단점**: 검색은 풀스캔 → 본 미션 규모(개인 가계부 ~수만 건)에서는 문제 X. DB 도입까지 필요 없음.

### 3-2. 왜 제너레이터 스트리밍인가
- **메모리 안전**: `json.load(f)`로 전체 로드 vs `for line in f: yield json.loads(line)` — 100만 건이어도 메모리 1줄치만.
- **조기 종료 가능**: `list -limit 10`에서 10개 찾자마자 break 가능 (실제 코드는 정렬을 위해 일부 버퍼링).
- **함수 합성**: `search` → `_filtered` → `export_csv` 가 모두 이터레이터를 받아 그대로 통과. PDF 과제 목표 3번 답변.

### 3-3. 왜 원자적 교체인가 (update/delete)
- 그냥 같은 파일을 열어서 쓰면 도중에 멈출 때 **반쪽짜리 파일** 가능 → 데이터 손실.
- `tempfile.mkstemp` → 임시 파일에 완성본 작성 → `os.replace(tmp, real)` 한 줄로 원자적 교체.
- `os.replace`는 POSIX/Windows 모두 atomic rename 보장.
- 실패 시 임시 파일 unlink로 정리, 원본 파일은 무사.

### 3-4. 왜 데코레이터로 예외 처리인가
- 모든 명령마다 `try: ... except: ...` 쓰면 중복 + 형식 불일치.
- `@trace_errors`를 `main`에 한 번 적용 → 모든 명령이 동일한 오류 출력 형식 + exit code 2.
- ValueError(검증 실패), FileNotFoundError(데이터 디렉토리 누락), 그 외 예외를 **타입별 분기 처리**.
- 스택트레이스 출력 금지(PDF 제약) — 사용자에게는 "원인 + 힌트"만.
- PDF 과제 목표 4번 답변.

### 3-5. 왜 dataclass인가
- `Transaction.amount: int`처럼 **타입 힌트가 곧 계약**.
- `__init__` / `__repr__` / `__eq__` 자동 생성 — 보일러플레이트 0.
- JSON ↔ 객체 변환이 `Transaction(**d)` / `tx.__dict__` 한 줄.
- PDF 과제 목표 5번 답변.

## 4. 예상 질문 + 답변 (10개)

### Q1. 파일 락(file locking)은 왜 안 걸었나?
A: 개인 가계부라 동시 실행 가정 X. 동시성 필요하면 `fcntl.flock`이나 sqlite로 갈 것. 본 미션 범위에서는 오버스펙.

### Q2. `list_recent`에서 왜 `buf`를 limit*2로 잡았나?
A: 파일 순서가 시간순 보장 X (사용자가 과거 날짜 거래 추가 가능). 메모리 절약 + 정확한 최신순을 위해 limit*2 윈도우로 슬라이딩.

### Q3. `delete` 시 ID 없으면?
A: `delete_tx`가 `False` 반환 → CLI에서 `[오류] 없는 id: ...` 출력. 스택트레이스 X.

### Q4. CSV import에서 잘못된 행은?
A: try-except로 잡고 `skipped` 카운트만 증가. 전체 import는 계속. 마지막에 `imported=N, skipped=M` 같이 보고.

### Q5. 카테고리 삭제할 때 사용 중이면?
A: `remove_category`에서 트랜잭션 스트림을 한 번 돌아 `used` 체크. 사용 중이면 메시지로 거부 (안 A). PDF 요구사항.

### Q6. 데코레이터를 메서드마다 안 붙이고 main에만 붙인 이유는?
A: 모든 CLI 명령이 main을 통과하므로 main 한 곳이 단일 진입점. DRY. 메서드별 데코레이터 필요해지면 `@timed`처럼 추가 가능.

### Q7. `__pycache__`는 왜 .gitignore 안 했나?
A: `.gitignore`에 `__pycache__/` 포함 — 확인 필요. (실제로 포함되어 있어야 함)

### Q8. 예산 초과 경고는 어떻게 표시?
A: `summary` 출력에서 `expense > budget`이면 ` [⚠ 예산 초과]` 접미사 + 사용률 %.

### Q9. 타입 힌트 검증은 누가?
A: 런타임 강제는 X (Python 표준). mypy/pyright로 정적 분석. 또는 dataclass + 명시적 검증 함수 (`validate_date` 등)로 보강.

### Q10. 표준 라이브러리만 쓴 이유는?
A: PDF 제약사항 7번. 또한 외부 의존 없으면 배포·평가 환경에서 추가 설치 없이 그대로 실행 가능.

## 5. 시연 시나리오 (5분)

```bash
# 1. 헬프
python3 -m budget_app -h

# 2. 카테고리 확인 (기본 시드)
python3 -m budget_app category list

# 3. 거래 추가 (대화형)
python3 -m budget_app add
# → 2026-05-17 / expense / food / 12000 / 점심 / lunch

# 4. 목록 (최신순 스트리밍)
python3 -m budget_app list --limit 5

# 5. 검색 (조건 조합)
python3 -m budget_app search --from 2026-05-10 --to 2026-05-17 --category food --q 점심

# 6. 월별 요약 + 예산
python3 -m budget_app summary --month 2026-05 --top 3

# 7. 수정 (원자적 교체)
python3 -m budget_app update --id TX-000010 --memo "저녁 분식 (할인)"

# 8. CSV 내보내기
python3 -m budget_app export --out 2026-05.csv --month 2026-05

# 9. 오류 시연 (스택트레이스 X)
python3 -m budget_app add
# → 날짜 입력에 "2026-13-40" 입력 → "[오류] 날짜 형식이 올바르지 않습니다 (YYYY-MM-DD). [힌트] ..."
```

## 6. 모르면 안 되는 키워드

- **JSONL** = JSON Lines, 1줄당 1 JSON 객체
- **제너레이터** = `yield` 함수, lazy evaluation
- **dataclass** = `@dataclass` 데코레이터로 자동 생성되는 데이터 클래스
- **원자적(atomic)** = 도중 실패해도 "전부 성공 or 전부 실패" 보장
- **데코레이터** = 함수를 감싸는 함수, 공통 관심사 분리
- **타입 힌트** = `x: int` / `-> str` 같은 정적 타입 표기 (런타임 강제 X)
- **argparse** = 표준 라이브러리의 CLI 파서
- **표준 라이브러리** = pip 없이 Python 설치만으로 쓸 수 있는 모듈들
